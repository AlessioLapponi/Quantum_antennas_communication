# Quantum Antennas Communication — Gaussian Channel Simulation and Machine Learning Models

This project simulates the long-time interaction channel between two non-identical harmonic oscillator detectors and builds lightweight machine learning models to approximate the energy-constrained classical capacity $C_E(t)$.

The project follows the full workflow:

1. numerical simulation of the physical Gaussian channel;
2. diagnostic analysis of numerical reliability;
3. automated generation of training data;
4. curve-level machine learning modelling;
5. deployment through a Streamlit app.

The main physical parameters explored by the machine learning models are:

$$
\gamma_A,\quad \gamma_B,\quad \omega_A,\quad \omega_B.
$$

The numerical simulation page allows additional physical and numerical parameters to be modified.  
The machine learning models, instead, are trained with fixed values of all parameters except $\gamma_A,\gamma_B,\omega_A,\omega_B$.

---

<details>
<summary><strong>What this project does</strong></summary>

The goal is to study the effective Gaussian communication channel generated by the long-time interaction between two harmonic oscillator detectors.

The numerical simulation computes three main quantities.

### Transmissivity

The transmissivity $\tau(t)$ describes the effective signal-transfer strength of the channel. In this model, $\tau(t)$ can oscillate and may cross zero. These zero crossings can generate physical cusps or bounce-like structures in the capacity curve.

### Noise determinant

The quantity $W(t)$ is the determinant of the channel noise matrix:

$$
W(t)=\det N(t).
$$

It measures the effective noise contribution entering the Gaussian channel capacity formula.

### Energy-constrained classical capacity

The final quantity of interest is the energy-constrained classical capacity:

$$
C_E(t).
$$

It describes the classical information capacity of the effective Gaussian channel under an energy constraint $E$.

The simulation can become numerically difficult in some parameter regions because $\tau(t)$, $W(t)$, and the capacity formula may involve rapidly growing, oscillatory, or near-boundary behavior. For this reason, the project includes diagnostic tools to detect unreliable output regions before using the data for machine learning training.

</details>

<details>
<summary><strong>How the Streamlit app works</strong></summary>

The app has two pages.

## 1. Numerical simulation and diagnostics

This is the main page of the app. It runs the full numerical simulation and shows:

- $\tau(t)$;
- $W(t)$;
- $\log_{10}|\tau(t)|$ versus $\log_{10}\sqrt{W(t)}$;
- $C_E(t)$;
- reliability scores;
- invalid or low-reliability capacity points;
- local outlier diagnostics;
- $\tau$ discontinuity diagnostics.

The user can modify both physical and numerical parameters.

### Physical parameters

- $\gamma_A,\gamma_B$: detector coupling/friction-like parameters.
- $\omega_A,\omega_B$: detector frequencies.
- $m_A,m_B$: detector masses.
- $\sigma$: interaction-width parameter.
- $d$: causal delay/contact time.
- $E$: energy bound used in the capacity formula.

### Numerical parameters

- $t_{\max}$: final simulation time.
- $dt$: fine-grid integration time step. Lower values are more accurate but slower.
- Number of $W(t)$ / $C_E(t)$ time points: number of coarse time points where the noise and capacity are evaluated.
- Integral points for $W(t)$: number of integration points used in the noise calculation.
- $r_{\rm tol}$ and $a_{\rm tol}$: relative and absolute tolerances used by the numerical solver.

### Reliability and filtering parameters

- Training reliability threshold: minimum reliability score required for a point to be considered usable for machine learning training.
- $h$-domain tolerance: tolerance used near the domain boundary of the bosonic entropy function.
- $h$-margin scale: controls how strongly points close to the entropy-function domain boundary are penalized.
- determinant quality scale: controls how strictly the determinant-based quality filter penalizes unstable noise values.
- outlier window: local window used to detect suspicious jumps in $C_E(t)$.
- outlier threshold: sensitivity of the local capacity-outlier detector.
- outlier penalty $\alpha$: strength of the penalty assigned to detected outliers.
- $|\tau|$-bounce protection window: number of neighboring capacity points protected around physical bounce regions caused by $\tau(t)$ zero crossings.
- $\tau$ jump local window: number of neighboring fine-grid $\tau$ steps used to detect isolated numerical jumps.
- $\tau$ local jump factor: threshold used to flag a fine-grid $\tau$ step as numerically discontinuous.

## 2. Machine learning model comparison

The second page compares trained curve-level machine learning models.

The machine learning inputs are only:

$$
\gamma_A,\quad \gamma_B,\quad \omega_A,\quad \omega_B.
$$

The other parameters are fixed to the values used during training:

$$
\sigma=0.01,\quad d=1.0,\quad m_A=m_B=1.0,\quad E=100.0.
$$

The page can run:

- the compressed PCA-based scikit-learn machine learning model;
- the PyTorch curve-output neural network;
- optionally, the full numerical simulation for comparison.

The numerical simulation is not run unless selected, so the app can remain responsive when deployed.

</details>

## Project goal

The numerical simulation computes:

- the transmissivity $\tau(t)$;
- the noise determinant $W(t)$;
- the energy-constrained classical capacity $C_E(t)$.

The machine learning models approximate the full capacity curve:

$$
(\gamma_A,\gamma_B,\omega_A,\omega_B)
\longrightarrow
C_E(t_1),\ldots,C_E(t_{200}).
$$

This is useful because the full simulation can be slow and may become unstable in difficult parameter regions.

---

## Current machine learning strategy

Earlier pointwise machine learning models were tested:

$$
(\gamma_A,\gamma_B,\omega_A,\omega_B,t)\longrightarrow C_E(t).
$$

They captured the broad trend but often produced noisy, time-incoherent curves. For this reason, the current approach uses **curve-level machine learning models**, where the whole capacity curve is predicted at once.

The current machine learning models are:

- **PCA-ML curve model**  
  Uses Principal Component Analysis to represent $C_E(t)$ curves and a scikit-learn regression model to predict PCA coefficients.

- **PyTorch curve-output neural network**  
  Predicts the full $C_E(t)$ curve directly.

The PyTorch model is the main neural-network model. The PCA-ML model is included in compressed form to remain compatible with GitHub file-size limits.

In this project, the term **surrogate model** refers to a machine learning model trained to approximate the output of a slower numerical simulation.

## Main files

### `app.py`

Unified Streamlit app.

It contains two pages:

1. numerical simulation and diagnostics;
2. machine learning model comparison.

### `src/simulation.py`

Core numerical simulator.

It computes:

- Green functions;
- transmissivity $\tau(t)$;
- noise matrix $N(t)$;
- noise determinant $W(t)$;
- capacity $C_E(t)$;
- reliability scores;
- numerical discontinuity diagnostics.

### `src/bounce_detection.py`

Detects physical bounce/cusp regions caused by sign changes of $\tau(t)$.

The detection is based on fine-grid sign crossings:

$$
\tau(t_k)\tau(t_{k+1})<0.
$$

Small $|\tau(t)|$ values are not automatically classified as bounces unless a real sign change occurs.

### `src/torch_curve_models.py`

Defines the curve-output PyTorch neural network.

The model maps physical features to the full capacity curve:

$$
X_{\rm features}
\longrightarrow
C_E(t_1),\ldots,C_E(t_{200}).
$$

The architecture enforces:

- non-negative capacity through a positive output activation;
- causal zero response for $t<d$.

### `experiments/pointwise/`

Contains the earlier pointwise machine learning approach. These files are kept as experimental history but are not part of the main deployed app.

The final machine learning models were trained with:

```text

dt = 0.0005
number of W/C points = 200
n_integral_points = 400
rtol = 1e-8
atol = 1e-10
determinant_quality_scale = 1e-14
tau local jump factor = 100
```

Fixed physical values:

```text
sigma = 0.01
d = 1.0
m_A = 1.0
m_B = 1.0
E = 100.0
```

---

## Training domain

The machine learning training domain is:

$$
0.001 \leq \gamma_A,\gamma_B \leq 0.035,
$$

$$
0.1 \leq \omega_A,\omega_B \leq 1.5.
$$

To avoid strongly unstable asymmetric regimes, the training set is constrained by:

$$
|\gamma_A-\gamma_B|\leq 0.005,
$$

$$
|\omega_A-\omega_B|\leq 0.3.
$$

The machine learning comparison page warns the user when inputs are outside this domain.

---

## Generated physical features

The machine learning models are not trained only on raw parameters. They also use derived physical features, including:

$$
\gamma_{\rm mean},\quad
\Delta\gamma,\quad
|\Delta\gamma|,
$$

$$
\omega_{\rm mean},\quad
\Delta\omega,\quad
|\Delta\omega|,
$$

$$
\Sigma_A^2,\quad
\Sigma_B^2,\quad
\Sigma_{\rm mean}^2,\quad
\Delta\Sigma^2,
$$

and the delayed coupling factor:

$$
\frac{2\sqrt{\gamma_A\gamma_B}}{d}.
$$

Signed deltas are kept because the system is not symmetric under exchange of detector $A$ and detector $B$.

## Current machine-learning model limitations

The machine learning models are useful as lightweight approximations, but they are not yet a complete replacement for the numerical simulation.

The main difficulty is that $C_E(t)$ may contain physical cusps or bounce-like structures caused by zero crossings of $\tau(t)$. These are hard for generic machine learning regression models to reproduce, especially when the position of the cusp changes with the parameters.

The PCA-ML model is limited by the need to keep the model binary small enough for GitHub and deployment. A larger version of the model achieved better accuracy but exceeded standard GitHub file-size limits before compression. The included compressed model is therefore a compromise between accuracy and deployability.

The PyTorch curve neural network gives a coherent full-curve prediction, but it can still smooth out or misplace sharp bounce structures.

For this reason, the numerical simulation and diagnostic page remains the reference tool. The machine learning model comparison page should be understood as a first deployable approximation.

## Future machine-learning improvements

Future work will focus on improving the machine learning models without losing deployability.

Planned improvements include:

- a bounce-aware neural network architecture that jointly predicts $C_E(t)$ and a $\tau(t)=0$ bounce/cusp mask;
- model compression and quantization to reduce file size while preserving accuracy;
- alternative supervised machine learning models with lower storage cost;
- separate models for different dynamical regimes;
- uncertainty estimates to warn users when machine learning predictions are unreliable;
- larger and more targeted training datasets near difficult parameter regions.

The next natural model is a physics-informed or bounce-aware neural network with two outputs:

$$
(\gamma_A,\gamma_B,\omega_A,\omega_B)
\longrightarrow
\left(C_E(t),\;B(t)\right),
$$

where $B(t)$ is a learned mask indicating expected bounce/cusp regions associated with $\tau(t)=0$ crossings.
